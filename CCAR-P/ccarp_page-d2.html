2.3프롬프트 엔지니어링 기법 Prompt engineering techniques

제로샷 Zero-shot

지시만 주고 예시는 없습니다.

적합: 일반 학습만으로 패턴이 충분히 커버되는 단순하고 익숙한 작업

퓨샷 Few-shot

지시에 고품질 입출력 예시를 몇 개 더합니다.

적합: 원하는 형식, 엣지 케이스, 모델이 스스로 추론하지 못할 하우스 스타일. Anthropic 가이드는 캐싱으로 저렴해진 다양한 고품질 예시 20개 이상이 2~3개보다 나은 경우가 많다고 봅니다.

사고의 연쇄 Chain-of-thought (CoT)

답하기 전에 단계별로 추론하라고 지시하거나, 확정 전에 "생각할" 공간을 줍니다.

적합: 다단계 추론, 수학, 계획. 그럴듯하지만 틀린 답으로 건너뛰기 쉬운 곳
사고 기능과 CoT 프롬프트

최신 Claude 모델에서는 구조적 추론이 프롬프트 요령이 아니라 일급 기능(적응형/확장형 사고)으로 제공됩니다. 그래도 "단계별로 생각해" 같은 고전적 CoT 프롬프트는 그 기능이 꺼진 모델·모드에서, 그리고 검토자가 추론 과정을 감사할 수 있게 만들 때 여전히 유용합니다.

2.4컨텍스트 윈도와 토큰 관리 Context window optimization and token management

컨텍스트 윈도는 필요할지 모르는 모든 것을 쏟아 넣는 곳이 아니라 작업 기억의 예산입니다. 이 영역을 받치는 사실이 두 가지 있습니다.

컨텍스트 부패 Context rot

명목상 한도 안에서도 토큰이 늘수록 정확도와 회상이 떨어집니다. 더 많은 컨텍스트가 곧 더 좋은 것은 아닙니다. 무엇을 넣을지 가려내는 일이 남은 공간만큼 중요합니다.큐레이션

전부 센다 Everything counts

시스템 프롬프트, 모든 메시지(도구 결과·이미지·문서 포함), 도구 정의, 모델 자신의 출력(사고 토큰 포함)이 모두 윈도를 차지합니다.윈도 전체

최적화 수단 Practical levers

요약·압축 Summarization / compaction

오래된 턴을 주기적으로 짧은 요약으로 접습니다. 서버 측 기능으로 제공되는 경우가 늘고 있어 직접 만들 필요가 줄었습니다.

컨텍스트·도구 결과 편집 Context / tool-result editing

쓰임이 끝난 낡은 도구 결과나 대체된 중간 출력을 컨텍스트에서 지웁니다.

쑤셔 넣지 말고 검색 Retrieval instead of stuffing

큰 지식 베이스는 요청마다 관련된 조각만 가져옵니다. 코퍼스 전체를 매번 붙이지 않습니다(Domain 3의 RAG).

전송 전 토큰 세기 Token counting before sending

요청 전에 사용량을 추정해 예산을 지키고, 런타임에 넘치고서 알아차리는 일을 피합니다.

2.5프롬프트 재사용 Prompt reuse: caching, modular prompts, and Skills

프롬프트 캐싱 Prompt caching

아키텍트가 쥔 비용·지연 지렛대 중 가장 효과가 큰 것입니다. 변하지 않는 앞부분(시스템 지시, 정적 참고 문서, 도구 정의)을 캐시 대상으로 표시하면, 반복 요청이 이미 처리된 앞부분을 다시 처리하지 않고 재사용합니다. 비용(캐시 읽기는 새 입력 토큰의 작은 일부만 청구)과 첫 토큰까지의 시간이 함께 줄어듭니다.

도면 5 · 정적 내용을 앞에, 캐시 경계는 마지막 동일 블록에
시험의 설계 규칙

정적 내용을 먼저 두고, 캐시를 공유하려는 요청들 사이에 계속 동일한 마지막 블록에 캐시 경계를 둡니다. 요청마다 바뀌는 내용(타임스탬프, 실시간 사용자 메시지)에 경계를 두면 캐시 적중이 없고, 조용히 비용이 줄지 않고 늘어납니다.

모듈형 프롬프트 Modular prompts

큰 지시 묶음을 조합 가능한 조각(핵심 페르소나, 작업별, 출력 형식)으로 나눠 요청마다 조립합니다. 통짜 문자열보다 유지·테스트·독립 캐싱이 쉽습니다.

Skills Skills

지시, 스크립트, 참고 파일로 이루어진 재사용 절차 지식 묶음. Claude가 찾아서 관련될 때만 불러옵니다. 모든 기능의 지시를 항상 컨텍스트에 두지 않습니다.

원리: 점진적 공개. 필요할 때 기능을 불러오고 처음부터 전부 올리지 않습니다(Domain 3의 도구·컨텍스트 전략).

핵심 정리 Key takeaways: Domain 2

  • 모델 선택은 능력·지연·비용의 트레이드오프다. 모든 일에 모델 하나를 쓰지 말고 티어 사이로 라우팅한다.
  • 시스템 프롬프트가 주된 제어면이다. 순서는 역할, 참고 자료, 가드레일, 출력 형식.
  • 작업에 맞는 기법을 쓴다. 단순·익숙한 일은 제로샷, 형식·스타일 정밀도는 퓨샷, 다단계 추론은 사고의 연쇄.
  • 컨텍스트는 줄어드는 자원("컨텍스트 부패")이다. 적극적으로 가려내고, 압축·컨텍스트 편집·검색을 쓰며 쑤셔 넣지 않는다.
  • 프롬프트 캐싱은 뒤늦게 붙이는 기능이 아니라 설계 결정이다. 정적 우선 배치와 안정적인 캐시 경계가 실제 이득을 만든다.
