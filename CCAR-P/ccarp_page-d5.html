5.1가드레일과 안전 통제 Guardrails and safety controls

가드레일은 여러 층에 둡니다. 성숙한 설계는 한 가지에 의존하지 않고 여러 층을 동시에 씁니다.

도면 1 · 다섯 겹의 가드레일

입력 Input

들어오는 요청을 분류·필터링합니다. 프롬프트 인젝션, PII, 범위 밖 주제를 메인 모델 호출 전에 걸러냅니다.메인 호출 이전

시스템 프롬프트 System prompt

명시적인 행동 경계와 에스컬레이션 지침 (Domain 2).Domain 2

도구·행동 범위 Tool/action scope

출력 Output

별도의 분류기 호출이나 결정론적 코드가 생성된 응답을 한 번 더 검사합니다. 사용자에게 가거나 후속 행동을 일으키기 전에 정책 위반을 걸러냅니다.사용자 전달 이전

제거가 탐지보다 낫고, 탐지가 아무것도 안 하는 것보다 낫다. 기능이 존재하지 못하게 막는 것이, 오남용을 사후에 기록하거나 표시하는 것보다 강합니다.

5.2리스크와 실패 모드 Risks, limitations, and failure modes of LLM systems

핵심 실패 모드는 이름으로 말할 수 있어야 합니다.

도면 2 · 여섯 가지 실패 모드

환각 Hallucination

특히 근거 컨텍스트나 신뢰할 수 있는 지식 밖에서, 자신 있게 거짓이거나 검증할 수 없는 주장을 만듭니다.

프롬프트 인젝션 Prompt injection

검색된 문서, 도구 출력, 사용자 입력에 숨은 악성 지시가 시스템의 의도를 덮어쓰려 합니다. 에이전트가 웹 페이지·이메일·문서 같은 신뢰할 수 없는 외부 콘텐츠를 컨텍스트로 처리할 때 특히 위험합니다.

과도한 권한 Excessive agency

에이전트가 작업이 실제로 요구한 것보다 많은 행동을 합니다. 체크포인트가 부족한 다단계 자율 루프에서 두드러집니다.

데이터 유출 Data leakage

한 사용자의 컨텍스트, 검색된 문서, 학습 데이터의 민감 정보가 다른 사용자의 세션이나 출력에 부적절하게 나타납니다.

모델·지식 드리프트 Model/knowledge drift

모델 버전 업데이트, 데이터 갱신, 다른 곳에서 한 프롬프트 수정 같은 조용한 상류 변경 뒤에 동작이나 정확도가 달라집니다.

편향 증폭 Bias amplification

시스템이 특정 집단에 체계적으로 더 나쁘거나 불공정한 결과를 냅니다. 학습 데이터 패턴, 편향된 검색 코퍼스, 이를 못 잡은 대표성 없는 평가셋 때문일 수 있습니다.

5.3휴먼 인 더 루프 검증 Human-in-the-loop (HITL) validation strategies

모든 행동에 사람이 필요하지는 않습니다. 전부에 요구하면 자동화의 의미가 사라집니다. HITL을 리스크에 맞춰 조정합니다.

도면 3 · 리스크 등급이 오를수록 사람의 개입이 강해진다

낮음 Low

초안 생성, 내부 검색 요약. 사람 게이트는 필요 없고 표본으로 사후 검토합니다.사후 표본 검토

중간 Medium

고객 응대 답변, 티켓 분류. 보내기 전에 사람이 검토하거나, 통계적 표본을 계속 검토합니다.발송 전 또는 표본 상시

높음 High

환불, 계정 변경, 의료·법률 안내, 금융 거래. 행동이 실행되기 전에 사람의 승인이 매번 예외 없이 필요합니다.필수 승인
체크포인트 위치

HITL 체크포인트는 세션 시작이 아니라 되돌릴 수 없거나 영향이 큰 행동 지점에 둡니다. 작업을 시작해도 좋다고 승인받은 장시간 에이전트가, 이후 스스로 결정하는 모든 행동까지 미리 승인받은 것은 아닙니다.

5.4규제 준수 Regulatory compliance

변호사가 될 필요는 없습니다. 시나리오가 어느 규제를 촉발하는지, 그에 따른 아키텍처상 함의가 무엇인지 알아보면 됩니다.

도면 4 · 데이터·분야에서 규제와 통제로

GDPR EU personal data

데이터 최소화, 삭제·접근 권리, 명확한 적법 처리 근거. 국경 간 이전과 보존 규칙, 그리고 EU 개인정보를 다루는 AI 시스템이 무엇을 기록하고, 캐시하고, 보존하는지에 유의합니다.

HIPAA US protected health information

PHI를 다루는 모든 벤더와 업무 제휴 계약(BAA), 엄격한 접근 통제와 감사 로깅, 작업에 완전한 식별이 필요 없으면 비식별화.

FedRAMP US federal government cloud

인가·인증된 배포 환경과 데이터 상주, 암호화, 감사에 대한 엄격한 통제가 필요합니다. 나중에 "추가"할 수 없고, 기반 플랫폼과 호스팅이 이미 인가되어 있어야 합니다.

시험의 일관된 패턴

시나리오가 다루는 규제 대상 데이터·분야를 식별한 뒤(건강 데이터 → HIPAA, EU 시민 개인정보 → GDPR, 미국 연방 기관 → FedRAMP), 불필요한 데이터 노출을 줄이거나, 필요한 접근 통제·감사 추적을 더하거나, 알맞게 인가된 환경을 쓰는 선택지를 고릅니다. 면책 문구만 붙이거나 "모델은 정보만 줄 뿐"이라며 규제를 무시하는 선택지는 아닙니다.

5.5윤리적 AI Ethical AI: bias, fairness, and transparency

도면 5 · 윤리적 AI의 세 축

편향 Bias

전체 평균 정확도만 보지 말고 인구통계·사용 사례 슬라이스별로 출력을 적극 테스트합니다. 평균은 좋아 보여도 특정 하위 집단에서는 훨씬 나쁠 수 있습니다.하위 집단별 검증

공정성 Fairness

이해관계자와 함께 사용 사례에서 공정한 대우가 무엇인지 정의합니다. 결과의 평등, 대우의 평등, 기회의 평등은 서로 충돌할 수 있으므로 명시적 기준을 고르고 암묵에 맡기지 않습니다.명시적 기준 선택

투명성 Transparency

AI와 상호작용 중임, 사용하는 데이터, 알려진 한계를 사용자에게 알립니다. 채용, 대출, 의료, 법률처럼 영향이 큰 분야에서 특히 그렇습니다. 모델 선택, 가드레일, 알려진 실패 모드를 내부 문서로 남겨 사후에 감사 가능하게 합니다.공개 + 내부 문서화

핵심 정리 Key takeaways: Domain 5

  • 가드레일을 입력, 프롬프트, 도구 범위, 출력, 행동에 겹쳐 둡니다. 불필요한 기능의 제거가 탐지보다 낫고, 탐지가 아무것도 안 하는 것보다 낫습니다.
  • 핵심 실패 모드를 이름으로 압니다: 환각, 프롬프트 인젝션, 과도한 권한, 데이터 유출, 드리프트, 편향 증폭.
  • HITL을 리스크 등급에 맞추고, 체크포인트는 세션 시작이 아니라 되돌릴 수 없는 고영향 행동 지점에 둡니다.
  • 규제를 데이터·분야에 맞춥니다(GDPR: EU 개인정보, HIPAA: 미국 건강 데이터, FedRAMP: 미국 연방 클라우드). 면책 문구가 아니라 구조적으로 알맞은 통제를 고릅니다.
  • 하위 집단별 편향을 명시적으로 테스트하고, 공정성은 가정하지 말고 이해관계자와 정의하며, AI 사용·데이터·한계에 대한 투명성을 만듭니다.
